# 业务练习子项目 v2：功能与验收记录

## 本次目标

将原来偏接口演示的订单库存练习，扩展为有客户商城、运营后台、仓库与完整履约链路的可学习 Web 子项目。继续服务 Python、接口自动化、UI 自动化与性能练习，不引入真实支付和真实物流。

## 实现范围

入口：个人工作台 → 实践实验室 → 练习商店 → 打开独立业务页面。也可访问 `/practice-app`，先有平台登录态，再登录练习角色。四个练习账号及工程运行方法见 [practice/README.md](../practice/README.md)。

| 客户页面 | 运营/仓库页面 | 业务保障 |
| --- | --- | --- |
| 商城分类、搜索、库存筛选、排序、分页与详情 | 业务概览与待处理状态 | 本人独立 SQLite，四种角色权限 |
| 多商品购物车、明确保存数量与移除 | 商品新增、编辑、上下架 | 整数分核价、运费、商品/地址快照 |
| 地址增删改查、默认与格式校验 | 入库、预占、库存流水、CSV | 事务结算、防超卖、版本冲突 |
| 结算、付款、取消、订单回看 | 发货、退款通过/驳回、操作审计 | 请求幂等、重复取消/退款仅回补一次 |
| 收货、退款申请、订单时间线 | 历史v1兼容订单 | 未确认写入结果保留提交编号供核对 |

参考工程增加四角色 API 链路和实际 UI 页面测试。自动化使用专用客户购物车，不清空手动 learner 购物车，订单与审计保留。业务页采用中性浅色、蓝色操作、清楚的状态与响应布局。

## 数据兼容与上线

保留v1接口及旧表，商品只增加兼容字段。首次升级用 SQLite backup 创建 `.pre-v2.sqlite3`；主动重置才清空本人的业务练习数据并废止旧会话，不清除平台笔记、学习内容或报告。上线另备份平台数据库、所有个人练习数据库、源码与三个受影响服务镜像。只更新 backend/frontend/practice-runner，其他服务保留。

## 已完成本地验证

- 干净发布副本：后端126项、前端12项通过，构建通过。
- 真实参考工程：API 12项通过；UI 3项通过：下单取消、付款/跨角色发货/收货/退货退款、后台创建商品/入库/下载。
- 真实低负载Locust：1用户5秒、8次请求、0失败、P95约51ms，仅为本机小样本，不能代表生产容量。
- 独立页85组布局检查：1440/1280/768/390/320px，覆盖登录、客户、仓库、运营、订单详情、商品弹窗，无整页横向溢出、无未处理页面异常。
- 原平台23模块×5宽度，共115组布局回归通过。
- 独立实际登录、错误密码保留平台会话、地址格式/默认、数量更新、越权路由、平台内嵌业务、工程下载通过。
- 后端专项验证：多商品中途缺货完整回滚、两客户抢最后一件、价格/地址版本变化、订单与地址所有权、退款驳回/退货确认、下架、重置失效、旧库历史保留。

首轮UI发现并修复：搜索只读取初始商品列表、表单可访问名称不稳定、库存搜索定位器语义不符；修复后重跑3项全部通过。保留失败记录，不将首轮失败计为通过。

## 使用与练习建议

先手动走通客户→仓库→客户→管理员，随后从接口版pytest开始；再练页面定位、等待、跨角色上下文、截图/录像、重复操作、异常流程。最后用只读Locust观察错误率、吞吐和P95。将自己的代码改写、失败原因和测试证据写入学习笔记。

## 实际边界

付款、物流和退款均模拟，不连接真实外部业务。没有优惠券、促销、供应商采购或分布式库存；订单与流水接口最多返回最近300条。SQLite适合个人练习与小规模并发验证，不作生产电商容量承诺。布局与功能验收不等于获得任何设计奖项。

远端部署与隔离验收结果在完成后补充。
