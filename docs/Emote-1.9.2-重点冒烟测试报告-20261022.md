## 主要问题与复现

### E192-01｜P1：已占用昵称显示“可以使用”，保存未禁用

1. 测试账号 A：个人主页 → 编辑资料。
2. 输入已由测试账号 B 占用的昵称，等待查重完成。
3. 实际出现绿色“该昵称可以使用”，保存可点击。

真实响应：

```json
{"success":true,"code":200,"data":true,"message":"操作成功"}
```

空闲昵称则返回 `success=true, data=false`，同样显示可用。与要求中的“空闲 `data=null`、重名 `success=false/code=409`”不一致。

**影响：** 当前前端只按 `success` 判定可用，接到旧版后端响应时将已占用昵称错误放行。此处已经确认是实际联调失败，不能用新契约模拟通过抵消。

**建议：** 先确认 emote-test 后端是否已发布对应版本；如需要跨版本兼容，仅在昵称查重适配层区分旧布尔值与新契约。`success=false/code=409` 对应占用，其他拒绝保留后端原因。

[实际占用昵称被标可用截图](D:/Automation_Platform/output/emote-192/evidence/fail-nickname_duplicate.png)

### E192-02｜P2：500ms 防抖期间可点击保存

编辑资料后输入需检查的新昵称，在输入后约 100ms 检查按钮：保存仍可点击。用违规词输入也复现；本轮没有点击保存违规昵称。

**原因线索：** `EditProfileModal` 在定时器触发后才设为 checking；定时器等待期间仍保留 idle/旧状态。

**建议：** 昵称发生变化时立即置为待校验并禁用保存；提交时核对当前昵称与已验证昵称一致。增加请求序号或取消过期请求，避免旧响应覆盖新输入。原昵称未变化时可保持原有保存行为。

### E192-03｜P2：个人页删除本人动态后，卡片仍在列表

1. 新建仅用于本轮验证的本人私密帖子，收藏后进入个人主页“珍藏回声”。
2. 在该本人动态右上角菜单选择删除并确认。
3. `DELETE /posts/{postId}` 返回 HTTP 200、`success=true, data=true`。
4. 等待 4 秒后，该动态仍显示在当前收藏列表中；服务端删除已执行。

已同时用原始真实响应和浏览器转为 `data=null` 的响应复现，**不是仅由 data 结构变化引起**。首页相同操作可立即移除。

**原因线索：** 删除服务派发 `emote_moods_updated`；Profile 收藏列表监听收藏更新事件，没有对应移除已删除动态的处理。

**建议：** 删除成功后按帖子 ID 同步清理所有已加载列表及缓存；个人页收藏列表订阅删除事件，或统一发送收藏刷新事件。不要以强制刷新整页代替列表状态修复。

[个人页删除后仍显示截图](D:/Automation_Platform/output/emote-192/evidence/delete-profile-null.png)

### E192-04｜P2：好友备注无法保存

在“霖感小秘书”和一个普通好友的私聊页分别执行：右上角菜单 → 修改备注 → 输入合法长度备注 → 保存。

两者真实响应均为：

```json
{"success":false,"code":500,"message":"更新好友备注失败","data":null}
```

**注意：HTTP 状态为 200，500 是响应体内的业务码。** 未出现成功提示，顶部昵称没有更新。没有成功写入新备注，不应按“备注改好了但标题没刷新”归因。

**建议：** 核对后端好友关系、`userId/friendId/remark` 参数映射和对应日志；分别回归官方好友与普通好友。仅修改前端 success 判断不能解决此次真实接口失败。

### E192-05｜P2：举报成功后弹窗不关闭

仅向指定官方测试聊天对象发送本轮带时间戳测试消息，对这条自己新发的测试消息长按举报。

`POST /message-reports` 真实返回 `success=true`，出现“举报成功”，但举报弹窗持续显示；原因输入已被清空，提交按钮变成禁用。

**原因线索：** DirectChat 成功分支调用 `closeReportModal()`，关闭回调受 `!isReporting` 限制，而此时 finally 尚未复位 isReporting。

**建议：** 将“成功后的程序关闭”与“提交期间用户取消的保护”分开。不要简单在同一同步片段先 setIsReporting(false) 再调用仍读旧状态的回调。

[成功提示与未关闭弹窗截图](D:/Automation_Platform/output/emote-192/evidence/fail-message_report.png)

### E192-06｜P1（联调待定位）：注销冷静期登录缺少确认步骤

- 申请注销接口成功，页面正常退出至登录页，已验证。
- 使用该专用账号真实登录后，直接进入首页，未出现“账号注销冷静期”提示，未发起要求中的按钮取消请求。
- 已通过服务器内的补偿接口取消注销，最终再次登录及资料查询确认 A/B 均不在冷静期。

**尚未确认根因。** 不能把“直接登录到首页”解释为已成功通过取消注销按钮，也不能据此断言后端已自动撤销。需要核对 `/login.data.user` 与随后基础资料接口是否都保留 `deletionStartTime`，以及后端是否仍采用旧的自动撤销逻辑。当前登录适配器最终使用重新取得的基础资料对象，需要重点排查字段是否在此丢失。

**建议：** 对齐冷静期状态契约，在明确取消成功前不进入业务首页；取消失败保持提示并展示后端原因。

## 新响应契约补充验证（与真实联调分开）

| 场景 | 方法 | 结果 |
| --- | --- | --- |
| 空闲昵称 `success=true/data=null` | 模拟查重响应 | 显示可用，保存可点击，通过。 |
| 重名 `success=false/code=409` | 模拟查重响应 | 显示红色“该昵称不可使用”，保存禁用，功能通过；文案未按要求明确“已被占用”。 |
| 首页删帖 `success=true/data=null` | 真实删除新测试帖，仅在浏览器把响应 data 转为 null | 当前列表立即移除，通过。原始服务仍返回 data=true。 |
| 个人页删帖 data=null | 同上 | 当前收藏卡片仍存在，不通过；原始响应也复现。 |
| 冷静期弹窗 → 取消 → 首页 | 模拟基础资料冷静期字段与取消成功 data=null；没有再次申请注销 | 弹窗显示、确认后关闭并进入首页，通过。**仅证明前端成功契约路径，不代表真实环境该流程已通过。** |

## 其他观察与限制

- Web 页面存在未处理异常：`"Keyboard" plugin is not implemented on web`。本轮主要功能仍可操作，建议在调用原生插件前增加平台判断或错误处理。
- 冷静期弹窗的确认按钮当前文案为“确认”，不是要求中的“取消注销并登录”，建议改为明确动作。
- 由于遵守之前“新测试帖子保持私密”的要求，没有为了验证原野删帖创建公开新帖；该入口未算通过。
- 拉黑使用测试账号 B 已有的公开动态；黑名单及恢复已核对，但首页/原野所有分页和缓存的用户动态过滤未做完整验证。
- 本轮为指定八类功能专项冒烟，不是注册、签到、录屏等全平台完整回归；没有把模拟响应结果计作真实接口成功。
