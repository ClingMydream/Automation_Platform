## 用例变化

- **发帖**：A、B 分别随机心情及标签，发布带时间戳的私密帖，全部保留。只有未修改的内置旧步骤自动迁移为双账号流程，自定义步骤不覆盖。
- **首页日行一善**：从首页入口发布私密时间戳记录，再核对每日任务状态；当天已完成则验证完成状态、不重复领奖。
- **每日任务日行一善**：从每日任务入口完成并验证状态，也支持当天已完成分支。
- **浇水**：新增独立场景；每日任务流程也复用它。先给自己浇水，遇到明确的 24 小时冷却响应后改给霖感小秘书浇水。两个目标都冷却时记录保护分支通过，明确本轮未重复浇水；其他接口错误仍失败。
- **切换头像**：新增独立场景，随机另一个图标并保存，重新打开核对；保留昵称和签名。原修改资料场景仍修改头像与时间戳签名。
- **双账号任务互评**：用户后续明确授权公开后启用，取代之前暂缓互评的安排。普通双账号发帖仍私密，仅此场景使用公开测试内容。

## AI 任务互评流程

1. 经真实登录核对 A/B 身份，读取双方日行一善、相关评论/互动任务及首页挑战要求。
2. 服务器调用现有 DeepSeek，生成 A/B 两篇任务帖及分别回应对方帖子的两条评论。任务文本仅作为输入数据，不执行其中的指令；账号凭据不送给模型。
3. 未完成日行一善时从每日任务入口发布公开挑战帖并核对完成状态；已完成时按任务主题发布公开测试帖用于互评，不重复领取任务奖励。
4. A 评论 B、B 评论 A；正文均追加时间戳及“自动化测试”标识。
5. 使用浏览器实际发帖请求中的 UUID 打开明确的帖子详情，通过 UI 评论；重新打开双方帖子确认评论持久化。帖子、评论和执行检查说明全部保留，B 的关键页面另存截图。
6. 恢复原来的私密帖引用，防止后续收藏等场景误用公开测试帖。B 账号登录态同样使用 24 小时缓存，普通复用不续期。

内部 AI 接口仅允许 Runner Token 调用。密钥只在平台后端使用，不返回前端或执行日志。未配置或生成失败时在发帖前停止，明确记录前置受限，不用模板假装 AI 结果。
